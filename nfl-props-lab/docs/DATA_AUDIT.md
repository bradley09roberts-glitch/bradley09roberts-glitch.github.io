# Data audit (25 October 2026)

What we can lawfully and reliably use, what we hold, and what is blocked. Cited source
notes: [docs/research/nflverse_nfl_weather_2026-10-25.md](research/nflverse_nfl_weather_2026-10-25.md)
and [docs/research/odds_providers_2026-10-25.md](research/odds_providers_2026-10-25.md).
Measured coverage (rows per dataset and season, retrieval times, hashes, field
missingness) is regenerated by `npl audit` into
[reports/coverage/COVERAGE.md](../reports/coverage/COVERAGE.md).

## 2. Ingested for audit only (not model inputs)

| Source | Why not used |
|---|---|
| `snap_counts` (PFR) and `pfr_advstats` | Sports Reference terms §5 (May 2023) prohibit using its content for "supporting machine learning methods used to predict…". Decision D-002. Snap share is therefore not a feature; opportunity comes from pbp targets/carries/dropbacks. |
| `ftn_charting` | In-season in 2026 (weeks 1-7 present, 24 Oct), but earlier seasons were last modified after their seasons ended, so what was available each historical week cannot be shown. Usable later for a separately named research model, or prospectively from our own retrieval times. |
| `ngs_*` | NGS only publishes players above attempt minimums; not needed for the core markets yet. |

## 3. Not available / blocked

| Need | Status | Exact blocker |
|---|---|---|
| Bookmaker prices (any) | **US books only, research reference** | Updated 3 Nov 2026. The Odds API key is configured (D-018); one month of historical lines was bought (D-040). Current prices (all git-ignored under `data/`): player props per event (`npl quotes`), game lines for the whole slate (`game_lines`, below) and closing snapshots of tracked props (`npl close`). Every pull opens with the free events call and makes no paid call that would leave fewer than `NPL_ODDS_FLOOR` credits (default 400). |
| UK-accessible prop prices | **Unavailable** | On 26 Oct the `uk` region listed only game markets (match odds, spreads, totals), no player props, for the NFL (D-018); no UK bookmaker is listed for NBA props. US prices are stored only as `research_reference`, never as UK-accessible. |
| Game-day inactive lists (late edition) | **Unavailable** | Published ~90 minutes before kickoff; NFL.com terms §1.3 prohibit systematic retrieval without written consent. No permitted feed. |
| Timestamped injury history | **Unavailable** | nflverse injuries have no publication time (the dictionary's `date_modified` is absent in 2025/2026 files). |
| Pre-kickoff weather forecasts (history) | **Not integrated** | Observed weather would leak. Open-Meteo's Historical Forecast API stitches the first hours of each run (close to observed). Its Previous Runs API holds 1-7 day lead forecasts mostly from Jan 2024; a weather experiment would be 2024+ only and separately labelled. Free tier is non-commercial, CC-BY 4.0. |
| Routes / route participation before cutoff | **Unavailable** | Participation (with routes) arrives after each season. |
| Preseason | **Absent** | nflverse schedules and stats carry no preseason games; nothing to exclude, and preseason is not modelled. |
| Paid alternatives | Not requested | SportsDataIO free-trial data is scrambled ("cannot be used for analysis"); Discovery Lab Odds USD 99/month, next-day delayed. Sportradar trials are real data but player props cover US books only; no public pricing. |

## 4. Identity audit

- Canonical player id = NFL GSIS id. Cross-ids come only from explicit id columns
  (players directory, then weekly rosters); never from names.
- Offensive player-game rows whose PFR id does not map: 133 of 133,701 (0.1%). Stat rows
  whose GSIS id is not in the players directory: 306 of 258,715 (0.12%); their names
  come from the stats file.
- Roster pfr/gsis pairs where sources disagree are flagged `CONFLICT` in
  `player_id_map.evidence`, not merged (2 pfr ids, 4 gsis ids at the 25 Oct build).
- Relocations are mapped to franchise codes: OAK→LV, SD→LAC, STL→LA.
- The Odds API returns player **names only** (no ids). Any future quote must be linked
  through an audited name+team+event mapping with manual review of ambiguous cases;
  until linked, `quotes.player_id` stays NULL and the quote is unusable for betting.

## 5. Freshness (from the 25 Oct 02:40 UTC ingest)

pbp/stats/rosters/injuries/depth charts updated 24 Oct (nflverse daily ~07:00-13:00
UTC); 2026 data runs through the Thursday Week 7 game (NE at CHI). nflverse notes that
Thursday's pbp is the cleanest after Monday-Wednesday stat corrections, so stat
corrections are handled as new raw versions (append-only settlement revisions).

## 6. NBA (added 28 Oct 2026, D-019)

Audited 28 Oct 2026. Base URL `https://github.com/sportsdataverse/sportsdataverse-data/releases/download/<tag>/<file>`;
seasons are named by their ending year (2027 = 2026-27). Licence: repository MIT, data
labelled CC BY 4.0 (credit: SportsDataverse). Content originates from ESPN game feeds.

| Dataset | Tag / file | Coverage | Use |
|---|---|---|---|
| Player box scores | `espn_nba_player_boxscores/player_box_{s}.parquet` | 1994-2027 | outcomes, minutes, starters, did-not-play with reason |
| Team box scores | `espn_nba_team_boxscores/team_box_{s}.parquet` | 1994-2027 | card extras only (`npl.nba.extras`, 3 Nov 2026): the opponent's assists allowed and defensive rebound % this regular season; team totals for usage and the model are summed from player rows |
| Schedules | `espn_nba_schedules/nba_schedule_{s}.parquet` | 1994-2027, includes future games with UTC tip-off times | live slates |
| Injuries | `espn_nba_injuries/injuries_{s}.parquet` | 2027 only, one snapshot a day (about 18:40 UTC) since 8 Sep 2026 | live P(plays) only; no history, so not backtested. Since D-046 the only injury source for editions: each edition records the snapshot's date and published time (the file's Last-Modified) and says that later injury news is not included. Cards show the structured fields of the snapshot the edition used (body part or reason, area, detail, side, expected return date) |
| Depth charts | `espn_nba_depthcharts/depthcharts_{s}.parquet` | 2027 only | not used |
| Play-by-play | `espn_nba_pbp/play_by_play_{s}.parquet` | 2002-2027 (2023-2027 ingested) | shot locations (raw coordinates, basket at (25, 0)), free throws, fouls by type and fouler; points by quarter (scorer = athlete 1) for the cards' fourth-quarter share |
| Team box scores | `espn_nba_team_boxscores/team_box_{s}.parquet` | 1994-2027 (2016-2027 ingested) | see above: assists allowed and DREB% on cards; other totals are summed from player rows |

Play-by-play checks (28 Oct 2026): field-goal attempts per team-game equal the box score in
80% of team-games and are within 2 in 99.5% (5,430 team-games, 2023-2027); shooter position
unknown for under 0.01% of attempts. The fouled player is not recorded, so fouls drawn by
position are unavailable. ESPN lists one position per player per game (G, F or C); PG, SG,
SF and PF appear on about 0.3% of rows and are not used.

Freshness: game data lands about 11:45 UTC the morning after (07:45 ET); same-day results
are not available, and since D-046 nothing fills the gap (a team on the second night of a
back-to-back is forecast without the previous night's game until SportsDataverse has it).

Not used:
* **NBA official injury report** (official.nba.com PDFs): NBA.com Terms of Use sect. 9(iv),
  "the NBA Statistics may not be used in connection with any gambling activity (including
  legal gambling activity)".
* **ESPN site, APIs or image server directly**: Disney Terms of Use sect. 2.B.x forbid access
  "using a robot, spider, script, or other automated means". From 29 Oct to 3 Nov 2026 the app
  fetched ESPN's public game feeds for provisional box scores (D-025) and publish-time injury
  reports (D-033), against D-019 (D-045). Since D-046 (3 Nov 2026) nothing is fetched from any
  ESPN host: box scores come only from SportsDataverse, editions use its daily injury snapshot,
  and the HTTP helper refuses ESPN and NBA.com addresses outright (`util.BLOCKED_HOSTS`). The
  feeds already stored stay in the raw store (source `espn`), unused.
* **Photos and logos**: NBA player photos and every team and league logo (NFL and NBA) came from
  ESPN's image server (`a.espncdn.com`, the addresses listed in the nflverse teams table and the
  SportsDataverse box scores). Since D-046 they are not downloaded: the thumbnails cached before
  3 Nov 2026 under `data/headshots/` and `data/logos/` are still shown, and a player or team
  without one shows initials or the team's abbreviation. NFL player photos come from the
  nflverse headshot address (`static.www.nfl.com`).
* **stats.nba.com-derived releases** (`nba_stats_*`): same NBA.com gambling clause.
* **Basketball-Reference**: Sports Reference terms (as for the NFL).
* Injury-snapshot comment text (`short_comment`, `long_comment`) is third-party news copy:
  not shown in the app or committed.

Odds: The Odds API lists NBA player props (`player_points`, `player_rebounds`,
`player_assists`, `player_threes`, `player_points_rebounds_assists`, alternates and
combos) mainly at US books and DFS sites; no UK bookmaker is listed for NBA props.
* Props (`npl quotes --sport nba`): one event-odds call per game for the core markets, with no
  `/markets` pre-call (event odds cost only the unique markets returned, and an event without
  props costs nothing).
* Game lines (taken by the same command; `--no-game-lines` skips them): one featured-markets
  call, `GET /v4/sports/basketball_nba/odds?regions=us&markets=h2h,spreads,totals&oddsFormat=decimal`,
  covers the whole slate for 3 credits. Every bookmaker, market and outcome row goes to the
  append-only SQLite table `game_lines` (moneyline, spread, total; linked to SportsDataverse
  game ids like prop quotes). Validated on a real response on 3 Nov 2026: 10 games, 7 US
  books, 246 rows, all linked. The call also returns games already under way; their lines are
  in-play (`game_lines_frame(pregame=True)` leaves them out).
* Closing snapshots (`npl close --sport nba --within MINUTES [--dry-run]`): for games with props
  on the paper record that tip off within the window, one event-odds call per game for the
  tracked markets only, stored like any quote, so closing-line value uses a snapshot taken
  minutes before tip-off.
* Card extras (`npl.nba.extras`, 3 Nov 2026) read stored lines only, never fill one in: the
  consensus line (`npl.books`) of each past game's snapshot nearest before tip-off, from
  `hist_quotes` for 2024-25 and the 2025-26 sample and from `quotes` for 2026-27, and the
  pre-game `game_lines` (median spread and total over regulated books, best regulated
  moneyline). The historical consensus is cached in `data/nba/lake/prop_lines_hist.parquet`
  (git-ignored, rebuilt when `hist_quotes` changes).

### ESPN game feeds (29 Oct - 3 Nov 2026; stopped by D-046)
ESPN's public game-summary feed (`site.api.espn.com`, no key) was fetched for finished games
SportsDataverse had not published yet (D-025) and, before tip-off, for each game's injury report
(D-033). About 220 feeds are stored unchanged under raw/espn/ (nba_summary,
nba_pregame_summary). Nothing reads or fetches them now; `npl.nba.espn` keeps only the parsers,
for audit.
